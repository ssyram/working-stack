# Working Stack：语义管理

## 入口

前提：`working-stack` 已在 PATH。首次使用先读 `working-stack doc ENTRY`，按入口索引查所需文档。本 skill 规定如何理解和维护内容，不重复 CLI 参数、文件格式或手工日志规则。

## 栈为谁服务

工作栈属于用户，AI 协助维护。它保存用户的目标、注意力、真实进度、返回条件和下一步，不是聊天流水账、完整项目设计或 AI 内部 todo。用户应能回答：现在做什么、为何做、做到什么算结束、之后回哪里。

- 工作线有独立目的；根帧保留原目的和边界。不能用最近产物、工具需求或实现便利替换用户目标。
- 帧是用户可见的理解/裁决上下文。计划项是帧内工作；普通执行步骤留在计划中，不为每次工具调用造帧。确有需要独立目标和回程的上下文才进入子帧；独立旁支须说明来源。
- para 保留同父多个未结束分支，但注意力焦点最多一个，也可全部暂停。焦点/暂停不表示进程运行/停止；后台成果回填不能自动抢走焦点。

## 推进与结束

- 新上下文是 push；返回已有暂停位置是恢复，不是重新建帧。切换注意力不等于完成或放弃旧分支。
- 暂停保留当前责任和回程；写清在等哪个决定、事实或证据。停止执行不自动代表目标达成。
- Done 要对应原目标，多个目标须全部达成；计划全打勾、报告交付或工具成功都不是用户验收。用户保留的判断不能由 AI 代签。
- 用户结束/替换未达回合用 Expired，保留已得成果、未完义务、退出理由与承接位置。仅暂挂不要退出；一支完成不自动完成兄弟或父目标。
- 计划耗尽而目标未达时，指出缺口并寻找有依据的下一步，不改写目标凑成功。原则和成果按需要承接，不向所有祖先重复抄录。

## 内容与历史

- 计划、已执行、已验证、已接受分开。事实、报告、推导、用户确认的原则分开；重要性或命令句不产生规范效力。
- 结果回答本帧目标获得了什么；待核判断、背景及目标外线索放备注。共享 note 保存一份内容，可由多处引用，不把全局内容塞进每个帧。
- 关闭时对照原目标说明正向达成、反向推翻、以及有来源的额外收获，逐点给依据；只写实际发生的方向，不凑分类。
- 退出前逐条判断原则去向：局部保留、上移承接、因前提失效推翻，或将误列的事实转入结果/备注。按责任和用户裁决处理，Expired 不自动上移原则；工具只登记处置，不替操作者判断。
- 保留真实历史，不将后来的成功倒写成当时已知。误记应有据更正并保留原判断、理由及未完义务；不要把正常新回合冒充旧帧复活。
- 只记录改变目标、判断、边界或下一步的非平凡信息。修改提供有信息量的原因，由工具生成记录；不要另手写日志、补造旧时间或重复维护派生标记。
- 结构校验只能说明形式合法，不能证明目标正确、历史真实或用户已接受。维护栈本身不授权业务修改、实验、额外审查或后台工作。

## 全局导览与复工理解

`notes["description"]`约定为本栈导览：解释用户工作范围及必要材料所在位置，Markdown中直接位于#标题之后。不另抄一份目标/进度账。可以写“全局约束见note累计原则”，由调用方按需读取；需要在context中直接取得正文时，用已有`{{note:累计原则.body}}`引用。不要为了示例强制创建该note，更不能复制一份并行权威。

`working-stack STACK show context`取回导览、当前责任链及已有正文；无焦点不自动切换，必要时用`show context ID`。普通指路不会自动展开，显式引用会展开；长备查材料应只定位，不无条件插值。这个视图提供工作理解的材料，不自行判继续理由、证据可信或审批。

维护目的不是填齐栏目，而是让继任者能据同一组已知材料理解当前责任、依据及行动边界，从正确位置继续。任务为何仍相关、主张据何成立、行动由谁允许分别判断；执行进展不能替代后两者。已录入快照可能缺本次对话，必须带最新裁决和真实执行增量理解它。

新信息改变了目的、继续理由、成立依据或行动边界时，更新其责任所属内容及真实受影响的父计划；不只往最新子帧追加消息，也不为无变化的字段造更新。原进入原因留在origin/PUSH历史；现在为何继续写在合适正文，不倒写成最初就知道。没有统一“当前判断”模板或每帧必填清单。

旧当前项被替代时，get定位后set替换结果/计划，或用`update --remark '标题=正文'`覆盖备注；原操作的原因应解释变化。log只记原因和变更字段，不是被替换正文的完整备份，仍解释当前判断的旧成果/反例要保留在适当正文或既有工件/Git中。多帧可用YAML候选apply，但当前没有提交前预览。

AI内部工具调用、worker调度与瞬时计数不等于WS用户工作的范围。只将改变用户理解、成果边界、阻塞或下一步的信息回填；副作用按实际回执记录，注意力暂停不表示后台停止。报告收到不代签结论接受，修改栈不产生业务执行授权。阻塞时保留恢复条件，并继续已授权且不受阻塞的工作。

更新后的context应能承接本轮形成的工作理解，不留旧路线让接手者重新推导；需要什么只补读什么，不默认全历史审查。正文完整、结构绿或输出变短均不证明校准充分。收尾短报焦点、成果边界、剩余责任及下一步；用户保留的判断仍交用户。

## 完整实战案例

需要从零学习具体管理过程时，读 [从 init 到验收的脱敏模拟](references/practice.md)：包含计划插入/拆分/重拟/重排/删除、多para、改挂帧、原则承接、误关闭更正，以及逐阶段真实MD/YAML、diff和完整命令回执。业务事实是模拟设定，不能照抄为自己任务的完成或用户确认。

## 最小文档指引

- 工具用法、安装、文档全量索引：`working-stack doc ENTRY`。
- 一次恢复方向及替换当前事实的recipe：`working-stack doc context-view`。
- push/pop/pause/resume、计划状态、常用查询与 JSON 输入：`working-stack doc ai-manual`。
- 按路径读取/编辑、插入、删除、移动及整段计划替换：`working-stack doc path-edit/README`。

需要其他格式或导入规则时，从 ENTRY 索引按需读取；不要照旧手工文档习惯猜命令或生成文件。
