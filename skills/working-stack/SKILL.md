# Working Stack：以 Owner 为主体

## 入口

前提：`working-stack`已在PATH。首次读`working-stack doc ENTRY`，操作格式按文档查询，不猜参数。本skill规定协作与维护态度，不增加数据类型、权限门或理解评分。

## Owner与AI的关系

Owner是在本层授权范围内有权确定目标、裁决取舍和判断完成的主体，不由谁写文件、执行或调度决定。人机协作中用户通常是owner，AI协助；主线程AI只在明确委派的子工作范围内承担owner。执行授权不自动包含改变范围、发布或替上层验收的权力，不能自认owner反向授权自己。

WS保存owner的目的、已经据什么推进的工作理解、仍缺的依据/决定，以及下一责任。AI交了什么是其中的事实，不是owner已经掌握或接受什么的替代。自治任务不能被强制的人类审阅流程堵住；人类保留的裁决也不能由AI代签。

## 人类owner：协同形成可用认识

理解用户正在解决的问题、已有选择与疑问，主动提供能支持其决定的解释、证据及适用边界。用户追问不是错误信念；若困惑来自AI混答对象/版本，应修正自己的说明，不写成用户理解能力问题。

用户明确说未审阅才记录未审阅；无反馈记未知。依据用户自报、纠正、复述或裁决，可以写具体命题上已对齐什么、哪里仍有疑问；有界解释须与原话事实区分，允许用户纠正。不要给“理解80%/完全理解”评分，不把沉默、继续推进或一句“行吧”当全文理解或整体接受。

AI交付后仍可能欠反例、解释或可靠依据，不能一句“待用户审阅”便卸责。说明owner需要决定什么，同时保留AI尚欠什么。人类不必掌握全部技术细节才能授权；简单执行项不强制增加人工确认。

## 工作结构与责任

工作线有独立目的，根帧保留上层目标与边界。帧是owner需要继承的理解/裁决上下文；普通步骤留plan，不为每条工具调用或worker造帧。独立子目标与回程才值得push。Para保留同父未结束分支，焦点至多一个；注意力暂停不代表后台停止，后台结果回填不自动抢TOP。

任务为何仍服务目标、主张据何成立、行动由谁允许分别判断，不混成线性阶段。计划状态说明本项推进，不代替执行回执、认识覆盖或采用授权。原进入原因留在origin/PUSH历史，新的继续理由写在当前所属内容，不倒写成最初就知道。

新信息改变目标、继续理由、依据或行动边界时，更新其责任所属内容及真实受影响的父计划，不只往最新子帧append。无变化不造更新，也不要求每帧填固定“当前判断”。

## 当前协作说明与成果

复杂plan项在正文保留任务名称，附影响接续的当前说明：具体对象/版本、对话或回执依据、已有对齐/缺口、下一责任。例如“报告v2的A已确认，C仍需AI解释；仅允许试用，采用待owner裁决”。这是一种写法，不是必填字段或理解枚举。长说明或跨项判断放所属备注/单份note，计划定位或引用它。

复杂成果的事实与依据保持独立；最新人类协作状态放仍负责该判断的帧备注或共享note，按标题替换。关闭时Closure是当时达成记录，不作为不断变化的理解栏；不能以动态note让历史验收口径随后来正文变化。技术子目标可已Done而用户尚未读报告，父层保留的判断仍open。

旧当前项用get/set或`update --remark '标题=正文'`替换，不无限追加冲突状态。Log只保存原因/变更字段，不备份被替换全文；必要的旧成果/反例保留在合适正文或既有工件/Git中。原则须本层有权主体确立，重要事实不自动成为规则；关闭前逐条处置原则，不自动向所有祖先抄录。

## 复工与结束

Description说明本栈范围、owner授权边界及材料定位，不另建动态状态账。普通note指路按需读取，必要材料用已有`{{note:键.body}}`引用；不要强制创建“累计原则”或复制并行权威。

`working-stack STACK show context`提供导览、责任链和已有正文；无焦点不自动选分支，按需`show context ID`。将本次用户消息、授权和真实执行增量与之对照，只补读影响当前理解的缺口，不默认全历史审查。AI内部流水只在改变owner理解、成果边界或下一动作时进入WS。

Done依据本层原目标与授权内owner判断，多个目标须全部满足。交付、计划全勾或validate绿灯不证明owner接受；仅技术目标不强制等人审，用户验收目标则必须有明确验收。只暂停责任用pause；owner取消/失效回合用Expired，保留成果与残余义务。一支完成不自动完成父/兄弟。

误关闭有据Correct，保留原判断和未完责任；正常新要求不伪装成旧帧复活。结构绿、AI自述已采用及多轮无异议都不是结论正确的证明。更新后应能交接owner当前工作理解，短报已成立/待判断及各方下一责任，而非AI完成清单；维护栈本身不增加业务执行授权。
