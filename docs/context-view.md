# 继承WS范围内的工作理解

## 目的与边界

`working-stack STACK show context [ID]`从现有栈取回复工材料，供人/AI恢复本层owner的目的、工作理解、当前责任与继续依据。默认使用唯一焦点；没有焦点则显示导览、live根目标和暂停末端，不自动resume。显式ID只查看该分支，包括关闭快照。

Owner由真实委托确定，不由执行者/文件作者决定；人类主导时用户为owner，明确委派的子工作中主线程AI可作本层判断。工具不判自由文本是否过时、报告是否可信、owner理解到哪里或是否接受。本次对话可能尚未入栈；调用方须对照最新裁决与真实执行增量。记录时间不是事实观察时间，frame/plan进度不是外部进程状态，结论成立不产生执行授权。

## 导览与材料定位

全局`description` note解释本栈范围和信息组织，打印为#标题下段落；不再做第二份动态进度账。先理解导览再看责任链。没有导览时不自动创建空note。

普通文字“约束见note累计原则”供AI按需查询：

```sh
working-stack mytask note '累计原则'
```

若该内容每次复工都必须取得，可在导览写`{{note:累计原则.body}}`，context复用现有resolver展开。提及名字不自动展开或赋予规范效力；备查长材料以普通文字定位，不无条件插值。材料仍保留一个责任所属源，不为导览另抄一份。

## 查询合同

导览始终在前。所选根→帧路径显示全部目标/原来源、未完成计划及get/set位置、已有FOCUS、全部已记录结果、外部执行事项、备注/原则、暂停原因或关闭摘要。结果不再只取最近三条，正文不统一截断240字符；显式引用展开并列出直接来源路径，可指向notes或关闭帧成果。关闭时计划标为快照，不是当前待执行。

取材范围止于导览、所选父链、暂停末端和正文显式引用；不无条件读全部notes、所有关闭帧或完整日志。最近事件只给时间/动作，历史按需show log/timeline读取。无FOCUS明确未指定，ready项不自动成为具体下一步。使用边界不冒充“下一步”的语义结论。

完整材料不等于短输出，历史瞬时状态仍混在正文时，context也会长。调用方维护当前正文及引用，工具不按词语、年龄或位置猜哪些可丢弃。没有新meta过滤器、自动摘要或语义校准门。

函数只读WorkingStack，不改持久化、事件、状态机或JSON请求schema。`show --json`仍返回原有Out，正文位于text；CLI与Web复用同一查询。

## Owner中心的内容维护

视图显示的是已录入正文，不是“AI任务完成率”或用户认识评分。调用方应让它能回答owner要求什么、已有选择/纠正、AI交了什么、具体哪些点已对齐或仍待解释，以及双方下一责任。报告已交不表示人类已读；无反馈只表示未知，不自动写未审阅。用户提问不是错误信念。AI尚欠依据/说明时不能用“待用户”隐藏自身工作；授权内的技术自治也不强制加人审关卡。

复杂计划正文可附有对象/版本及来源的协作说明；成果的最新人类状态可在当前责任帧备注/单份note按标题覆盖，关闭时Closure保留当时口径。示例与归属约定见`working-stack doc owner-collaboration`，无需修改字段、角色ID或状态枚举。

继任者能恢复owner工作理解与行动边界才是目的，字段齐全不是完成判据。新裁决使父计划或继续理由失效时，在其所属位置修改；原进入历史不倒写。执行记录不代替可信结论，可信结论不代替保留给owner/上层的批准。AI内部流水只在影响owner工作理解时进入WS，不能以全部工具调用作为工作本体。

用法示例，不是每次必走的程序：

```sh
working-stack mytask show context
working-stack mytask get 'T-02.results[0]' --json
working-stack mytask set 'T-02.results[0]' --value '"报告已返回，结论待确认"' -r '收到真实回执，替换旧运行状态，不代签结论'
working-stack mytask update T-02 --remark '当前边界=报告已收到，用户尚未接受' -r '同步当前审批边界'
working-stack mytask show context
```

历史log只保留原因与变更字段，不自动备份全部旧正文；仍影响判断的成果/反例须保留在适当正文或已有工件/Git中。瞬时监护细节放运行evidence，WS收敛到改变判断的信息。

多帧同步复用export yaml → 编辑/比较候选 → apply。当前apply直接校验保存后才返回diff，没有dry-run/preview；多个顺序update也不是整批事务。此次没有改变提交回执、自动写后context或核心diff用途。

## 测试和效果边界

直接测试证明导览、较早结果、长审批条件、执行记录和显式引用被呈现；无焦点/显式分支不resume，查询不落盘。模拟案例和真实WS副本检查模型往返，原件不改。

实战反馈已确认入口可用、替换recipe有效，同时确认旧正文仍需维护；焦点与内容都曾变动，不能把输出长度变化当工具提速或准确率证明。语义充分和用户验收不由结构测试保证。
