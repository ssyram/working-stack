# Markdown 未解析内容保留

依据用户确认：不能识别格式不等于内容无归属。核心模型不变，不新增计划状态或原文对象类型。

- 已识别内容继续使用现有核心字段；Principle/ClosureItem 的生成格式按 `markdown-fields.md` 分别保存 rule/fate、result/evidence，完整字段往返不能只靠备注相等判定。
- 帧内未识别栏目、子标题及其正文进入该帧 `remarks`，以原栏目名称标识；未知计划状态/无法解析的计划行进入“导入原文 · 计划”备注，不猜测状态。
- 无帧归属的未识别内容进入现有全局 `import-cache` note。
- 未解析文本作为字面 SourcefulText 保存；其中模板花括号不擅自解释为栈引用。
- Markdown 输出对备注及 note 正文逐行缩进，避免正文中的 bullet 或 `##` 被再次导入为结构；插值使用 SourcefulText 的现有格式化转义。再次导入恢复正文，不改变其归属。

函数合同：扫描未知栏目时，持续缓冲至下一个已识别栏目/子标题；结束时归入当前帧备注。单行解析失败时，把该行及所属栏目存入当前帧备注并保留 warning。每个消费分支要么建立核心字段，要么建立备注/note；warning 不能成为唯一内容载体。输出器的缩进与导入器去缩进互为逆过程。

测试职责：用真实 WS-MAIN 检查此前丢失的原则、待办、checklist 全表和未知状态原文在正确帧的备注内，push 不改变旧模型，重印后再次导入仍保留这些备注；全局未知小节的多行正文同样往返。不因此宣称全部历史字段的语义映射或整体原文逐字一致。
