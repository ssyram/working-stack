# Q

本工具以owner为本层主体：恢复其目的、工作理解及未完成责任，不以AI执行盘点推认识完成。Owner由明确授权关系确定；人类协作与局部AI自治共用现有模型，协作指引见owner-collaboration.md，不新增理解状态或权限引擎。

## Q.I（规范定义）

### Q.I.1 — 单文件权威
**采纳状态**：confirmed（用户原话："一个 WS file 就是核心，所有查询、调用、修改，都是基于这个 WS file"）
**定义**：工具的全部状态承载于一个 WS 文件；任何查询、修改、视图都以该文件（经核心库解析）为唯一权威源。
**判断力**：引入第二份需人工同步的状态表示（总览副本、平行数据库）即违规；派生缓存/导出不违规。
**适用边界**：单个 store（一个文件）之内；跨 store 关系不在本工具承诺内。

### Q.I.2 — CLI 为核心操作面，Web 同源
**采纳状态**：confirmed（"以命令行操作为核心（以后是 AI 执行的），以其他方式为视图，但是我可以网页端以本质调用和命令行一样的 API 的方式调用它"）
**定义**：CLI 是权威操作接口，语义面向 AI 可机械执行设计；Web 是视图+操作前端，与 CLI 调用**同一核心库 API**，不另设状态逻辑。
**判断力**：任何"只有网页能做/只有 CLI 能做"的状态变更即违规；UI 便利封装不违规。

### Q.I.3 — 操作必带原因，日志自动
**采纳状态**：confirmed（"日志 log 是自动的，每个操作填个原因，自动 log 起来就行"）
**定义**：每次修改操作必须携带 reason；变更记录（Event：行为、时刻、detail含reason及必要净变更摘要）由工具自动生成并追加，人/AI 不手写日志。
**判断力**：要求用户手工编写 change-log 即违规；机械字段缺失（时间/行为）即违规。

### Q.I.4 — 语义判断保留给人/AI
**采纳状态**：confirmed（沿承已确立原则：content/语义归人/AI，确定结构归脚本）
**定义**：语义判断由授权范围内owner负责，操作者依据实际委托/材料登记；工具只机械检查结构、引用与字段完备。执行授权不等于范围/发布/验收权，声明已采用也不证明客观正确。人类是否审阅、具体对齐/疑问必须有对象及来源；工具不评分或读心。
**判断力**：从结构绿灯、AI交付或执行进度推出owner已理解/接受或目标已达成即违规；用人审义务封死已授权的局部自治也不符合原目的。

### Q.I.5 — 可移植、易运行
**采纳状态**：confirmed（排除 Haskell 的理由："多平台不稳定，运行非常麻烦"）
**定义**：交付物在主流平台（macOS/Linux/Windows）以最小依赖运行；AI 在命令行可直接调用，无需运行时装配。
**判断力**：需要目标机安装解释器/虚拟机/大型运行时即违规。

### Q.I.6 — 非目标边界
**采纳状态**：confirmed
**定义**：不做云同步、多用户账号、自动语义验收、进程/agent 调度、与特定 AI 宿主耦合。
**判断力**：为上述能力引入的机制均为越界。

### Q.I.7 — 工具内文档入口与伴随分发
**采纳状态**：confirmed（用户要求 doc 动态列举、实际 ENTRY.md 置顶、环境变量覆盖；debug 用编译目录，release 本地及发布均用二进制旁 documentation）
**定义**：裸命令/帮助指向实际入口文档；文档列表动态扫描，支持嵌套路径与可选 .md 后缀。WS_DOCUMENTATION_PATH 优先覆盖；release 安装/下载包应带伴随 documentation，debug 默认用编译时 docs。入口不设虚构别名，不额外内嵌正文。
**判断力**：帮助、读取器和安装/发布脚本必须承接同一约定；不能把 Cargo 只装二进制说成已带文档。
