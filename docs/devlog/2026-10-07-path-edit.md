# 按路径内容编辑

## 目的与设计

用户要求用现有路径索引直接选择 insert 等操作，满足原位编辑、前后插入、拆分、删除/重排与整段重拟。具体 P/M/R 与调用格式统一位于 `docs/path-edit/README.md`；architecture、detailed-design、ENTRY、AI manual 和 README 同步引用。

## 实际实现

- `stack_path.rs` 复用 parse_ref 词法，定位实际模型字段，并为 content 简写补地址；get 返回原始结构值，不展开显示引用。
- `path_edit.rs` 在内存 JSON 候选完成 set/insert/remove/move，反序列化后由 CLI 复用 apply_events、apply_checks、validate/save。没有另造状态逻辑。
- 计划项字符串简写：新建为 Ready；set 既有项的字符串仅改正文，保留 progress/children/fork。对象和数组表示完整替换；progress 复用现有状态简写。
- 操作域是内容字段和 note body/meta；身份、parent、生命周期、原则处置和日志由既有专用操作拥有。
- 原候选通道对 note 变更的栈级原因事件现已接线，以支持新增 note 路径编辑；原因仍按已有非空合同检查。
- CLI/JSON 和 Web 请求共用转换器；Web get 直接返回结构值。网页没有新增视觉按钮，本轮交付的是命令/API。

## 未完成边界

此前多栈测试中的 note尾换行、native goal多行/引用重印问题不由本轮路径编辑修复。命令级MD测试使用符合已有家族语法的带标题文件；测试过程中还确认 native无title导出MD后不能重新导入（缺#标题），不将此当成路径编辑通过的证据。本轮未改这个独立输出边界。

索引是当前位置，重排不自动改写引用。move目标按移除来源后的结构解释。get实际结构路径不自动成为新的SourcefulText可展开引用路径。
