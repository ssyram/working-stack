# Owner中心协作：SKILL、文档与完整教程

## 目的

用户要求大范围同步SKILL/docs及完整教程，体现owner的工作与认识进程，尤其人类协作；同时推荐复杂plan/achievement项的最新人类状态标记。只改指导与案例，核心结构和操作不改，独立recalibration方法文件不改。

## 设计与实际改动

owner-collaboration.md承接方法：owner来自本层授权，不等于执行/调度者；工作推进、主张依据与行动权限分别成立。人类提问不是错误信念，无反馈只能未知；AI交付不推用户理解/采用，用户待裁决不隐藏AI尚欠的解释。明确技术委派允许局部主线程判断完成，不在每项强制加人审。

SKILL完整重写，手册及原则/架构/细化/ENTRY/context/路径/字段/时间线/notes/JSON文档与README同步。早期设计和UI历史只加现行协作入口，不重写旧历史或声称完成浏览器验收。

复杂plan保持任务正文，附有对象/版本/依据的短协作说明；长内容放所属备注/note。成果事实与依据独立，最新人类状态推荐按语义标题覆盖当前责任备注；ClosureItem是关闭时口径，不作为动态理解栏，不新增理解等级或角色ID。

教程重写为owner主体：H01–H09明确设定用户委托、提问、裁决/取消、对齐与有限采用；R1/R2为模拟技术回执。保留init/para/计划编辑/改挂/原则/Expired/Correct/JSON/时间线，加入局部AI技术owner与人类欠项协同，不只替换称谓。真实输出保存在references/practice-output-owner，旧版实物保持原时间。
